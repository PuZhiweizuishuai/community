## git push 被拒（fetch first）处置

- 原因：**三方分叉**。共同祖先 `58898dc`；本地 `65d0c0b 升级后端`；GitHub `origin/master=13c8017`（dependabot PR #3，fastjson 1.2.31→1.2.83，仅改 pom.xml 一行）；Gitee `master=a5851bb`（2022 年的 `5222b48 更新依赖`：Boot 2.7.5 / MyBatis 2.2.2 / fastjson 2.0.16 / 移除 Redis Session / 端口 8079 + `a5851bb 修改验证码认证` 删除注册接口测试后门）。`origin` 配有两个 push URL（GitHub + Gitee），且两个远端彼此也不同步。
- 用户选择：合并两边历史、代码完全以本地 Boot 4.1.2 升级为准；只做本地整合，push 由用户自己执行。
- 执行：`git merge -s ours origin/master` + `git merge -s ours gitee/master`，两次合并前后 tree 均为 `5aa111c1685d5b684afcb37c38c46ba214350242`，**代码零变化**；两个远端引用都成为 HEAD 的祖先，可快进推送。合并提交 `bd7ee85`、`71105ca`。
- 网络坑：本环境 git fetch GitHub 报 `schannel ... CRYPT_E_REVOCATION_OFFLINE`。`http.schannelCheckRevoke=false` 无效；`http.sslBackend=openssl` 可用（保留证书校验，推荐）；`-c http.sslVerify=false` 也能通但会触发安全策略告警，不应常用。curl 加 `--ssl-no-revoke` 直连 GitHub 返回 200，说明网络本身通畅。Gitee 分支通过 `git fetch <gitee-url> master:refs/remotes/gitee/master` 拉到本地引用。
- 待办：用户执行 `git push origin master`（会同时推 GitHub 与 Gitee）。若之后再被拒，先 `git fetch` 再按同样方式合并。
- 后续：用户已成功推送（HEAD = origin/master = `71105ca`）。随后按用户要求修改 `origin`：用 `git remote set-url --delete origin https://gitee.com/puzhiweizuishuai/community.git` 删掉第二个 URL，此后推送只到 GitHub。该长期约定已写入 `.workbuddy/memory/MEMORY.md`。

## 修复：Vditor 代码块夜间模式（同日追加）

- **根因**：`Vditor.preview` 的 `mode:'dark'` 不切换代码高亮主题；`highlightRender` 运行时以 `<link id="vditorHljsStyle">` 从 `https://unpkg.com/vditor@4.0.1/dist/js/highlight.js/styles/{style}.min.css` 注入，默认固定 `github`（亮色），内容主题同理 `<link id="vditorContentTheme">` 默认 `light.css`。夜间下 `code.hljs` 仍是 `#fff` 背景 + `#24292e` 文字。
- **关键 API**：`IPreviewOptions.hljs.style` + `IPreviewOptions.theme.current/path`；`Vditor.prototype.setTheme(theme, contentTheme, codeTheme, contentThemePath)` 一次切换三者；`Vditor.setCodeTheme(codeTheme, cdn)` / `setContentTheme(theme, path)`。可用暗色高亮名：`github-dark`、`github-dark-dimmed`、`monokai` 等（见 `Constants.CODE_THEME`）；内容主题名 `dark` / `light`。
- **实现**：新增 `web/src/utils/vditorTheme.js`（从 `vditor/package.json` 读 version 拼 CDN，导出 `vditorPreviewTheme(isDark)`）；`MarkdownView.vue` 展开到 `Vditor.preview`；`VditorEditor.vue` 的 `preview` 展开 + 主题 watcher 改 `editor.setTheme(t.editor,t.content,t.code)`；`main.css` 加 `[data-theme='dark']` 作用域的 GitHub Dark `.hljs*` token 配色兜底（优先级高于 CDN 注入样式）。
- 验证：夜间 `github-dark.min.css` + `dark.css`、代码块 `rgb(11,17,32)`/文字 `rgb(201,209,217)`/关键字 `rgb(255,123,114)`；白天自动切回 `github.min.css` + `light.css`；编辑器实时切换也同步；手动移除两个 `<link>` 后本地兜底仍暗色；build/lint 通过、控制台 0 错误。

## 修复：日间代码块外圈黑框（同日追加）

- **根因**：`.markdown-body pre` 的 `background` 写死 `#0f172a`，白天 `code.hljs` 是 `github.min.css` 的 `#fff` 白底，pre 的 16px padding + 圆角就围出一圈深色框；夜间两者都深色所以此前没暴露。
- **修复**：`main.css` 抽 `--code-block-bg` / `--code-block-color`（白天 `#ffffff`/`#24292e`，夜间 `#0b1120`/`#c9d1d9`）；`.markdown-body pre` 用变量 + 1px `--soft-border` 边框；新增 `.markdown-body pre > code, .markdown-body pre > code.hljs { display:block; padding:0; background:transparent; color:inherit; border-radius:0; overflow-x:auto }` 消除 Vditor 给 code 单独加的背景与二次 padding；删除夜间兜底块里冲突的 `padding:1em` / `padding:3px 5px` 覆盖，改用变量。
- **关键经验**：Vditor 的 `pre code.hljs{padding:1em}` 与 `.hljs{background:...}` 是 CDN 样式（0,1,2 / 0,1,0），本地要用 `.markdown-body pre > code.hljs`（0,2,2）才能稳定覆盖；底色与内边距统一交给 `pre`，不要让两层各自设背景。
- 验证：白天 `pre=rgb(255,255,255)`、`code=transparent`、边框 `rgb(226,232,240)`、关键字 `rgb(215,58,73)`，截图确认黑框消失；夜间 `pre`/`code` 均 `rgb(11,17,32)` 且高亮正常；build/lint 通过、控制台 0 错误。截图里代码块右下角的白色小胶囊是 Vite `vue-devtools__panel`（仅开发环境），不是样式问题。
