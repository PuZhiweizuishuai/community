## 后端代码安全审计（生产部署前）

- 对 `src/main/java/com/buguagaoshu/community` 全部后端代码做了公网部署前的安全审计，产出报告：`docs/后端安全审计与优化方案.md`。
- 审计结论：安全基础扎实（BCrypt、SQL 全参数化、路径穿越防护、Session 反序列化白名单、验证码防重放、找回密码防枚举等均已正确实现），主要风险集中在三方面：
  1. 缺安全响应头（H-1，高）：无 X-Frame-Options/X-Content-Type-Options/HSTS/CSP，已给过滤器代码。
  2. 权限拦截器"默认放行"（M-1，中）：未标 @RequirePermission 的 /api/admin/** 接口直接放行，已给后台路径默认拒绝方案；已知遗漏 AdminQuestionApiController.deleteQuestion。
  3. 生产配置默认偏向开发态（L-1~L-7）：Cookie Secure=false、Redis 无密码、Swagger 默认开、HTTPS 未启用、CORS 仅 localhost 等。
- 其他中风险：登录限流无 IP 维度（撞库）、登录错误码区分账号/密码（用户枚举）、JWT payload 含 email/userName、非图片文件无魔数校验、封禁用户可注册新账号。
- SQL 注入：经子代理全量扫描 Mapper，100% #{} 参数化，无 ${} 拼接，无原生 SQL，确认安全。
- 报告含三批实施优先级，部署前必做项已标红。

## 按审计方案完成后端安全加固（HTTPS 由 Nginx 负责，应用层不配 server.ssl）

已全部落地并实测，细节见 `CHANGELOG.md` 2026-11-22 条目。要点：

- 新增 `config/SecurityHeadersFilter`：X-Frame-Options / nosniff / Referrer-Policy / Permissions-Policy / COOP / CSP，HTTPS 时加 HSTS；`/api/file/**` 跳过 CSP。CSP 开关：`app.security.csp-enabled` / `app.security.csp`。
- **CSP 与 Vditor 的坑**：Vditor 代码块「复制」按钮是内联 `onclick`，`script-src 'self'` 下被拦截（控制台报错、复制失效）。解法：`web/src/utils/vditorCsp.js` 抹掉内联属性 + 事件委托复制（结构是 `<pre><textarea>代码</textarea><span>[data-copy-code]</span></pre>`，文本要从 textarea 的 `value` 取）。首屏主题脚本也从 `index.html` 内联抽到 `web/public/theme-boot.js`。
- **SESSION cookie 的 Secure 开关不认 `server.servlet.session.cookie.secure`**：手工 `@EnableRedisHttpSession` 后 Boot 属性失效，必须在 `HttpSessionConfig` 显式声明 `CookieSerializer`（已加，读同一 `COOKIE_SECURE`）。记住我 `token` cookie 走 `app.cookie.secure`。
- `PermissionInterceptor` 改为后台路径默认拒绝，白名单只有 `/api/admin/login|logout|session`；作者删帖改走 `DELETE /api/questions/{id}`（后台 `/api/admin/delete/question` 只给管理员，补了 `@RequirePermission`）。
- 新增 `application-prod.yml`（关 Swagger、Cookie Secure 默认 true、`spring.config.import: optional:classpath:application-local.yml` 复用本地凭据）；`server.forward-headers-strategy: native`（限流 IP 与 HSTS 依赖它）。
- 登录：邮箱+IP 双维度限流（5/15min 与 30/15min），失败统一「邮箱或密码错误」，日志用 `StringUtil.maskEmail` 脱敏。
- 密码规则升级为 8~30 位且含字母+数字（`StringUtil.PASSWORD_REGEX/PASSWORD_MESSAGE`），前端统一走 `web/src/utils/validate.js`。
- 文件上传改为全类型魔数校验（`FileUtil.detectMagicType` / `isMagicConsistent`，只读前 16 字节）。
- 评论：新增作者删除 `DELETE /api/comment/{id}`（软删除 + 计数回退），问题详情页对本人评论给出删除按钮。

**测试环境验证手段（本机无 mysql/redis CLI）**：
- 查库：`java -cp <mysql-connector-j.jar> Q.java`（单文件源码模式，`cygpath -w` 转换路径）。
- 读 Spring Session 的验证码：`/dev/tcp` 直连 Redis 发 `HGETALL spring:session:sessions:<base64 解出的 sessionId>`，字段 `sessionAttr:captcha` 的值在长度行之后。
- 坑：`curl ... | head -c N` 会因 SIGPIPE 导致 cookie jar 不落盘；要先 `-o file` 再读文件。
